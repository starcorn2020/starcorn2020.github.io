How do I work with AI?

I work as the architect, directing multiple AI agents that each take a different role in development.

Who does what

I decide

  • Architecture and system boundaries
  • Constraints: latency, and how failures should behave
  • Trade-offs and acceptance criteria
  • What gets merged

AI agents, by role

  • Research: reads the code and docs, and cites its sources
  • Implementation: writes code, refactors and docs
  • Testing: writes and runs tests
  • Review: checks each diff against the constraints

How a task goes

  1. Read first

    The research agent reads the code, docs and schemas before anything is proposed.

  2. Set the rules

    I define the boundaries, the invariants and what should happen on failure.

  3. Split the work

    Tasks are small enough to review one at a time, and each goes to the agent with the matching role.

  4. Build and run

    The implementation agent writes the code and the testing agent runs the tests. The compiler, tests and benchmarks decide whether it works.

  5. Review and record

    The review agent checks the diff against the constraints. I then check the result against the acceptance criteria and record what was confirmed.

Catching wrong answers

AI will sometimes make things up. I can't prevent that, but I can make it show up early.

Show the source
Every claim has to point to code, a spec, a test or real data. What the model remembers from training is not a source.
Unknown is an answer
If something can't be confirmed, it is marked unknown instead of guessed.
Only a run counts
“It works” means nothing until the tests pass or a real run shows it.

Memory across sessions

A long project outlives any single AI session. I keep design docs, decisions and confirmed findings in Notion and Markdown. At the start of a session, semantic search pulls in only the parts that matter for the task.

Only confirmed conclusions are written back, so one wrong answer doesn't get reused as fact later.

  1. Notes
  2. Search
  3. Session
  4. Verify
  5. Write back

In practice

  • Market Data Service

    A take-home assignment from a top proprietary trading firm. AI helped compare designs, generated the Rust code and planned the tests; I made the design and trade-off calls.

    The interviewer called it “the safest” design among the submissions.

  • EdgeX Singer

    A mid-2025 project, when AI was less capable. I found the math for AI to implement, then checked that every step matched the exchange bit for bit: curve arithmetic, Pedersen hash, order hash, deterministic signing, L2 fields, fees and key derivation.
